## Privacy

- Collect only account-linking data and service records; never location, IP geography, device fingerprints or page-by-page activity (Play Store minimisation).

## Coins and access

- All coin moves (track purchases, welcome/Battle rewards, VIP IDs, diss-track charges/refunds) go through authenticated server functions and service-only atomic, idempotent RPCs, so retries or client calls never duplicate or authorise coin changes.
- Coin ledger: a balance must always equal the sum of its coin_transactions. Every balance change writes a ledger row for exactly the amount applied (Boss take-aways go through src/lib/admin-coins.ts, which caps at the balance); never re-own or edit ledger rows. Audit, reconcile ("use ledger" / "keep balance") and the one-off reset live in src/lib/coin-audit.functions.ts (Boss → Money → Coin check).
- VIP IDs are `OG` + uppercase username via the service-only function, synced on username change.
- Sign in and Create account are separate tabs (EmailAuthPanel in src/routes/welcome.tsx): signing in never creates an account. Sign in takes a username, email or VIP ID (labelled "Username, email or VIP ID"); after the direct username/email attempt, src/lib/identifier-signin.functions.ts resolves a VIP ID or changed username and signs in on the server, returning only a session (never the email), with a per-identifier try limit.
- Boss account deletion: authenticated server function, server-checked role, protected targets.
- Boss member directory (src/lib/admin-members.functions.ts): every member loads in one server call (paged reads, no row cap); the list pages on the client. Account deletes everywhere go through src/components/admin/DeleteAccountDialog.tsx (type DELETE) and never offer Boss or Dev accounts. Member activity shows device type only, never location.
- Boss password reset (user settings): authenticated server function, server-checked role, protected targets; audit-logged without the password.
- Boss account merge (user settings, src/lib/admin-merge-accounts.functions.ts): server-checked role, duplicate must not be privileged; coins move via mint_coins_admin as the Boss (debit duplicate, credit main, never deduct_coins, which pays referral cashback); content is re-owned; the emptied duplicate is left for the Boss to delete; audit-logged.
- Telegram bot links to the site for a linked chat carry a one-time magic-link token (src/lib/telegram-signin.server.ts → /tg) so Telegram's in-app browser signs into the linked account instead of offering sign-up.
- Referral cashback: 6% of a referee's coin spend, 13% only for genuinely VIP leaders (never the intro offer), accrued in hundredths via pay_referral_cashback; none on VIP upgrades or card payments.
- Card-payment return checks (reconcileCoinSession, reconcileTrackUnlock) never pay referral rewards; reconcileCoinSession leaves `store:` sessions to the webhook, which credits store items once under its own reference.
- Settings (/settings) is the one account page for everyone: hero, Profile & identity (name, bio, VIP ID, Vault pass card), Membership & integrations, Preferences & coins, Security, then Boss controls for admins only, with a jump bar to each section and a one-line explanation under every section heading. Each card has its own tint and left stripe (SettingsCard tone) so sections stay visually separate; tints are borders and backgrounds only, never blue text. /profile redirects there. The Vault pass card (src/components/vip/OgVaultPassCard.tsx) only reads getVipPassStatus; its 2-hour credential rotation stays on the server.
- The finished-track card (src/components/library/FreshTrackCard.tsx) has no unlock step: tracks are paid before cooking, so it plays the full master and offers Download, Share and Edit.
- Store coin purchases (Sports Guide, Vault pass) always confirm price and balance-after first; the old Telegram Sports Guide invite function stays switched off.
- Tracks are paid before cooking via the pay step (src/components/library/PayChoiceDialog.tsx): coins_per_full_unlock coins through prepay_track, or £0.99 by card on the website (draft without a plan → track-unlock checkout → startGuestTrack once the unlock row exists). start_generation_charge still guards the minimum for unpaid samples.
- Guest tracks (website only, src/components/welcome/GuestStudio.tsx + src/lib/guest-track.functions.ts, whose card checkout/start functions members use too): a silent anonymous session stages a draft with no plan; the 99p card unlock (kind "track_unlock") pays for it; startGuestTrack attaches the plan only once the unlock row exists; claimGuestTracks moves paid tracks into the account after sign-in and drops unpaid drafts. ## AI

- Chat: free tiers (Groq, Pollinations, OpenRouter) first; paid Gemini only for media/"pro" or fallback. Foul Mouth on: only OpenRouter nemotron-3-super before Gemini. Live facts come from Gemini with Google Search grounding (getLiveResearchContext in src/lib/ai-endpoint.server.ts, started in parallel and only for clear live-fact asks, so the paid key isn't spent on small talk); OG Bot presents them in full persona. Perplexity is retired. The Foul Mouth free model gets 10s before Gemini takes over. Never Lovable AI or OpenAI for user inference.
- Lyrics: free tiers, then GEMINI_FREE_* keys, then paid Gemini; `GEMINI_BACKUP_API_KEY` only for lyrics after the primary fails. Offline songwriter if all fail; key failures go to ai_key_failures.
- Dictionary/intensity live in the songwriter prompt only; never reject lyrics for profanity density, and never auto-substitute words on moderation rejection.
- Battle Zone learns slang via service-only `learn_battle_words`; OG Bot openers come from the service-only catchphrase bank.
- Trade signals (messenger + Telegram): src/lib/trade-signal-context.server.ts detects a market + trade request, pulls live candles (Binance/Kraken for crypto and gold via PAXG, Yahoo for forex, indices, oil, $stocks) and computes indicators and the plan in code (src/lib/trade-signal.ts); every signal names the most likely direction with a confidence % (indicator agreement, never a win rate) and a UK-time "valid until" (scalp 1h, intraday 4h, swing 24h; Telegram signal replies self-destruct one 5-minute clean-up sweep before that); the model only presents those numbers and must say so when no data loads, never invent levels. Each signal also checks the live ticker just before sending (market entries use it), rates setup quality (Clean / Mixed / Choppy: ADX under 20 on the entry and middle frames means no clean setup), warns about high-impact news from the free weekly calendar for the market's currencies, and for crypto adds volume, Binance futures funding and open interest (src/lib/trade-signal-extras.ts); these extras are soft and capped at about 1.5s so they never delay a signal. Telegram signals are recorded in trade_signals and followed by a once-a-minute watcher (/api/public/trade-signal-watch → src/lib/trade-signal-tracker.server.ts, rules in src/lib/trade-signal-outcome.ts: closed 1-minute candles only, stop counts first when a candle touches both, stop moves to entry after TP1): members get a reply when the entry fills, a target or the stop is hit, the higher-timeframe trend flips before TP1, or time runs out, and the card carries a live price line. New signals show a 30-day track record for that market and timeframe once 5 have filled; the confidence % stays indicator agreement, never a win rate. Headlines from the Yahoo Finance search feed, soft-fail. Before the analysis the user gets an instant persona-toned "hold on" line from the shared catchphrase bank (kind trade_hold, pick_trade_hold via src/lib/trade-hold.server.ts): each user only ever gets lines they haven't seen, low supply adds AI-written lines and an exhausted user gets fresh fragment-built lines, both added for everyone; built-in holdingMessage is only the outage fallback (app fetches it via getTradeHoldLine, Telegram sends it first); it carries an invisible tag and is never fed back as chat history. In the app, signal replies carry a hidden [[SIGNAL_EXPIRES:…]] tag (from chatOgBot's signal_expires_at); once it passes the signal and its holding line collapse into an "expired, get a fresh signal" card, and cleanTradeHistory replaces expired signals in AI history so stale levels are never reused.
- OG Bot smarts (src/lib/og-smarts.server.ts, used by the app chat and Telegram, never Battle Zone): memory of each member in og_memories (short facts from private chat via a free-model extractor in src/lib/og-memory*.ts; never health, religion, sexuality, politics, addresses, contacts or payment details; members see, delete or switch it off in Settings, and off wipes it; in the privacy policy); football questions get ESPN scores, table, form and a code-computed lean (src/lib/football*.ts) before any paid web search; and replies built on live data pass a figures check (src/lib/fact-check.ts), with one rewrite if they quote numbers not in the data. Chat routing uses fetchAiChat's smart option (clean chat only; Foul Mouth keeps its original routing so the voice never softens): banter stays on free models, clearly hard questions go to Gemini first, and in-between questions get a 1.5s free Groq check that fails safe to free.
- Speed: the private chat streams through /api/og-chat (src/routes/api/og-chat.ts → runOgChat in src/lib/og-chat.server.ts, shared with the chatOgBot server function, which stays as the fallback); words show as they arrive and the final post-processed reply replaces the draft. Telegram streams the same way by sending the first words and editing the message (src/lib/telegram-live-reply.ts), with no artificial typing delay. Prep lookups run in parallel in all three chats. Foul Mouth: if the swearing model hasn't answered in 5s (aiTiming.foulHedgeMs), Gemini starts as a backup and the first answer wins. Battle Zone isn't streamed (shared room, short clapbacks).
- OG Bot reads images only; errors via src/lib/og-error-message.ts; buildSystemPrompt limits Boss Controls talk to admin/boss.
